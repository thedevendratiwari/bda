
# Real-Time Bank Transaction Pipeline

// 1. Problem Statement

A bank receives customer payment transactions continuously.

The bank wants to:

1. Send payment transactions to Kafka in real time.
2. Use a fraud-detection service to consume those transactions.
3. Automatically copy transaction-log data into an archive without writing a custom program.

We will implement this using:


//PART A

Payment Application
       |
       | Kafka Producer
       v
 Kafka Topic: payments
       |
       | Consumer
       v
Fraud Detection Service


And:


//PART B

Core Banking Log File
       |
       | Kafka Connect Source
       v
Kafka Topic: bank-transactions
       |
       | Kafka Connect Sink
       v
Archive File


2. First Understand the Important Components

Before executing, understand these terms.

| Component        | Simple meaning                                                            

| Producer         | Sends messages to Kafka                                                   |
| Topic            | Stores/organizes Kafka messages                                           |
| Partition        | Subdivision of a topic for parallel processing                            |
| Consumer         | Reads messages from Kafka                                                 |
| Consumer Group   | Group of consumers sharing the work                                       |
| Kafka Connect    | Moves data between Kafka and external systems without writing custom code |
| Source Connector | External system → Kafka                                                   |
| Sink Connector   | Kafka → External system                                                   |
| Offset           | Position of a message in a partition                                      

// Most important point

Kafka Connect is not another Kafka broker.

It is a framework/application that sits outside Kafka:


External System
      |
      v
Kafka Connect
      |
      v
Kafka


or:


Kafka
  |
  v
Kafka Connect
  |
  v
External System

Kafka Connect is a framework provided with Kafka for moving data between Kafka and external systems.

//Instead of writing a program like:

Configuration
+
Connector
=
Data movement

     |

     |

     |
     +------> Reporting


One transaction stream can therefore be consumed by multiple applications.

# 42. One-Line Definitions for Lab/Interview

| Term               | One-line answer                                                

| Kafka              | Distributed platform for real-time event streaming             |
| Producer           | Sends events/messages to Kafka                                 |
| Consumer           | Reads events/messages from Kafka                               |
| Topic              | Named stream where Kafka stores events                         |
| Partition          | Ordered subdivision of a Kafka topic                           |
| Offset             | Position of a message inside a partition                       |
| Consumer Group     | Group of consumers sharing topic partitions                    |
| Consumer Lag       | Difference between produced and consumed offsets               |
| Kafka Connect      | Framework for moving data between Kafka and external systems   |
| Source Connector   | Moves external data into Kafka                                 |
| Sink Connector     | Moves Kafka data to an external system                         |
| Converter          | Converts data between Kafka Connect/internal and Kafka formats |
| Standalone Mode    | Kafka Connect running as a single worker                       |
| Distributed Mode   | Multiple Connect workers working together                      |
| Replication Factor | Number of copies of each partition                             |

---

# 43. The Most Important Difference

Students often confuse these:

// Producer


Application → Kafka


Usually requires application code/API.

// Consumer


Kafka → Application


Usually requires application code/API.

// Kafka Connect


External System ↔ Kafka


Usually configured using connector properties instead of writing custom data-movement code.

---

# 44. Final Practical Flow

Your students should be able to explain the entire lab like this:

> The payment application acts as a Kafka producer and sends bank transactions to the `payments` topic. The fraud-detection service acts as a consumer in the `fraud-service` consumer group and processes the transactions in real time. For the second flow, Kafka Connect's Source Connector reads transactions from the core banking log file and publishes them to the `bank-transactions` topic. The Sink Connector then consumes those records from Kafka and writes them to the archive file. Thus, Kafka Connect provides configuration-based data movement between external systems and Kafka without writing custom producer or consumer code.
